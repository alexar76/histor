# Воспроизвести разбор обновлений MCP в HISTOR

[English](README.md) · [Русский](README.ru.md) · [Español](README.es.md) · [Français](README.fr.md) · [中文](README.zh.md)

Пример сравнивает шесть сохранённых синтетических наблюдений трёх зависимостей. Он связывает
изменения определений с четырьмя рабочими сценариями и даёт конкретные перепроверки перед
обновлением. Эти данные не описывают опубликованные пакеты, действующие endpoint или клиентские
развёртывания.

## Запустить из исходников

Нужен Python 3.11 или новее. Из каталога `histor/`; установка, ключи, модель и сеть не нужны:

```bash
python3 -m histor upgrade-brief \
  --lang ru \
  --watchlist examples/upgrade-brief/watchlist.ru.json \
  --out-dir ../output/histor-upgrade-brief-example/ru
python3 examples/upgrade-brief/verify.py \
  --out-dir ../output/histor-upgrade-brief-example
```

Используйте `.venv/bin/python` вместо `python3`, если это ваш интерпретатор Python 3.11+.
Первая команда создаёт `report.md` и `report.json`. Вторая дважды проверяет все пять языковых
watchlist по [expected.json](expected.json), сверяет побайтовую повторяемость результатов и
неизменность входов, затем выводит `PASS` и завершается с кодом `0`. Ошибка проверки даёт код
`1`. Отчёты сохраняются в папках `en/`, `ru/`, `es/`, `fr/`, `zh/`; повторный запуск заменяет
сгенерированные файлы.

Проверка также дважды запускает команду без `--lang` и требует побайтового совпадения с явным `--lang en`: всего 12 офлайн-запусков CLI. Основной `watchlist.json` — английский; `watchlist.en.json` остаётся его эквивалентным вариантом.

## Ожидаемый результат

Сводка: `changed: 1`, `unchanged: 0`, `context_changed: 1`, `unknown: 1`.

| Зависимость | Результат | Результат сценариев |
|---|---|---|
| `demo:research` | `changed`, определения сопоставимы | `weekly-review` и `archive-import`: `retest` |
| `demo:migration` | `context_changed`, изменился протокол | `status-check`: `unknown` |
| `demo:offline` | `unknown`, новое наблюдение неуспешно | `daily-status`: `unknown` |

Для `weekly-review` повторите сохранённый запрос `search_docs` с новым обязательным полем
`workspace`. Учтите, что `limit` теперь объявлен строкой, и измените чтение ответа с `items` на
`results`. Прочитайте изменившееся описание и проверьте выбор инструмента. У `export_brief`
`readOnlyHint` меняется с `true` на `false`, а `destructiveHint` — с `false` на `true`; проверьте
обработку подтверждений и разрешений перед тестовым экспортом. Эти hints — заявления сервера.

Для `archive-import` выбранный `legacy_fetch` удалён. Новый невыбранный инструмент
`fetch_document` принимает `id` вместо `document_id`. Изучите кандидата на замену, при
необходимости явно измените выбранные инструменты сценария и проверьте известный документ.
Разбор не объявляет новый инструмент автоматической заменой старому.

Для `status-check` определения `read_status` прежние, а протокол меняется с `2025-06-18` на
`2026-07-28`. Повторите наблюдения клиентом с поддержкой нужного протокола при одинаковых
условиях запуска и доступа. Для `daily-status` получите полное успешное новое наблюдение
до сравнения инструментов. Неуспешная попытка не доказывает удаление инструмента.

Проверочный скрипт сверяет определения и ожидаемую структуру отчёта. Перепроверки сценариев —
инструкции для вашего тестового стенда; пример не запускает MCP-серверы и не вызывает инструменты.

## Языковые версии и свои данные

| Язык | Watchlist |
|---|---|
| English | [watchlist.json](watchlist.json) |
| Русский | [watchlist.ru.json](watchlist.ru.json) |
| Español | [watchlist.es.json](watchlist.es.json) |
| Français | [watchlist.fr.json](watchlist.fr.json) |
| 中文 | [watchlist.zh.json](watchlist.zh.json) |

Версии переводят заголовки и описания сценариев, используя общие снимки, ID и выбранные
инструменты. `--lang ru|en|es|fr|zh` выбирает язык служебных пояснений, чеклистов, текстов
проверок и ограничений в JSON. По умолчанию используется английский (`en`). Имена полей, коды статусов,
диагностические причины, ID, схемы и хеши не меняются; поле JSON `language` сохраняет выбор.
Ваши заголовки, описания сценариев и фрагменты исходных определений сохраняются, поэтому
используйте соответствующий языку watchlist; входные данные автоматически не переводятся.

Для своих данных скопируйте набор в отдельный каталог, замените снимки, настройте выбранные
инструменты и сценарии. `expected.json` и `verify.py` относятся к этому фиксированному
синтетическому примеру; для других данных нужны другие ожидания. Отдельная команда `capture`
сохраняет HTTP-наблюдения с доступом к сети; подробнее в [руководстве](../../docs/upgrade-brief.ru.md).
