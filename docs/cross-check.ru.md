# Сверка с другим наблюдателем

[English](cross-check.md) · [Русский](cross-check.ru.md) · [Español](cross-check.es.md) · [Français](cross-check.fr.md) · [中文](cross-check.zh.md)

HISTOR не единственный сервис, который читает списки инструментов серверов из MCP Registry. Их читает и CrawlCheck
(crawlcheck.io), и с 7 ноября 2026 года он публикует тот же дайджест набора инструментов, что и HISTOR. Два
наблюдателя, которые читают сервер примерно в одно время и считают дайджест независимо, проверяют друг друга:
расхождение значит, что одному из них сервер отдал другое (например, отвечает по-разному разным клиентам или
регионам) или что у одного из них ошибка.

## Дайджест

Это дайджест набора инструментов MTL/1 ([labels.ru.md](labels.ru.md)). Для каждого инструмента: `name`,
`description` (`""`, если нет), `inputSchema` (`{}`, если нет) и `outputSchema`, только если сервер прислал объект;
инструменты отсортированы по имени в кодовых единицах UTF-16; канонический JSON по RFC 8785; SHA-256 в виде строки
SRI. В спецификации lockfile у CrawlCheck он называется `jcs_v1.tools_sha256`
(https://crawlcheck.io/spec/mcp-lockfile).

Проверено 7 ноября 2026 года: оба опубликованных тестовых вектора CrawlCheck, шесть наборов инструментов из записей
HISTOR, посчитанные сервисом CrawlCheck, и собственный сервер CrawlCheck дают у обеих сторон одинаковые дайджесты.
`annotations`, `title` и `icons` в этот дайджест не входят. Оба сервиса хранят их под вторым дайджестом, но строят
его по-разному, поэтому эти два не совпадают и не сравниваются.

## Ежедневный запуск

Каждый день в 12:00 UTC HISTOR читает публичную ленту изменений CrawlCheck
(https://crawlcheck.io/api/v1/mcp/changes, последние 500 событий, примерно два с половиной дня) и сравнивает каждое
событие с дайджестом с историей HISTOR для этого сервера (`/api/v1/servers/<id>`). Результат публикуется на
https://histor.modelmarket.dev/datasets/xcheck-crawlcheck/ в отдельной папке за каждый день: лента в том виде, в
каком её прочитали (`feed.input.json`), сравнение (`feed.report.json`, `feed.report.md`) и `SHA256SUMS`. `latest/`
ведёт на последний день. Расхождения публикуются как есть, без фильтра.

| Вердикт | Что значит |
|---|---|
| `agree` | дайджест HISTOR на момент чужого чтения тот же (между двумя чтениями HISTOR годится любое из них) |
| `agree_nearby` | у HISTOR в тот момент был другой дайджест, но этот HISTOR видел в пределах 24 часов: сервер сменился между чтениями |
| `disagree` | у HISTOR есть дайджесты в пределах 24 часов, и этого среди них нет |
| `histor_no_digest` | у HISTOR нет дайджеста для сервера в пределах 24 часов (не читал или список, который MTL/1 не может посчитать) |
| `not_listed` | HISTOR не знает такого имени и адреса |
| `bad_row` | поле отсутствует или не читается |

Окно в 24 часа нужно потому, что некоторые серверы меняют список при каждом чтении: 7 ноября четыре из семи
проверенных серверов получали новый дайджест примерно каждые 30 минут. Два наблюдателя тогда совпадают только
«рядом».

## Запустить самому

```bash
python3 scripts/xcheck_digests.py https://crawlcheck.io/api/v1/mcp/changes --out report.json --md report.md
```

Python 3.11 или новее, только стандартная библиотека. На вход — файл или https-адрес: лента изменений CrawlCheck в
опубликованном виде или любой список строк с полями `name` (имя в реестре), `endpoint`, `digest` (SRI или hex) и
`read_at` (RFC 3339) в JSON, JSON Lines или CSV. Код выхода 0 — ни одного `disagree`, 1 — хотя бы одно, 2 — вход не
прочитан.

## Первый результат

7 ноября 2026 года, первый запуск по ленте: 8 событий с дайджестом, 7 `agree`, 1 `histor_no_digest`, 0 `disagree`.
