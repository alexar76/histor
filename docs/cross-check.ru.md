# Сверки с другими наблюдателями

[English](cross-check.md) · [Русский](cross-check.ru.md) · [Español](cross-check.es.md) · [Français](cross-check.fr.md) · [中文](cross-check.zh.md)

HISTOR не единственный сервис, который читает списки инструментов серверов из MCP Registry. Наблюдатели, которые
независимо читают одни и те же серверы, проверяют друг друга: если они расходятся, значит, сервер ответил им
по-разному (разным клиентам, регионам или в разное время) или у одного из них ошибка. HISTOR по расписанию сверяет
свои записи с такими наблюдателями и публикует каждую сверку вместе с расхождениями в
https://histor.modelmarket.dev/datasets/peers/.

## Наблюдатели

| Наблюдатель | Способ | Расписание | Где опубликовано | С какого дня |
|---|---|---|---|---|
| CrawlCheck (crawlcheck.io) | дайджесты наборов инструментов | каждый день, 12:00 UTC | `/datasets/peers/crawlcheck/` | 2026-11-07 |
| ScraperWatch (scraperwatch.com) | изменения по полям | каждый день, 12:00 UTC | `/datasets/peers/scraperwatch/` | 2026-11-01 |

Список — это один файл настроек, `/etc/histor/peers.json` на хосте (`deploy/peers.json` в этом репозитории). Его
публичный вид — https://histor.modelmarket.dev/datasets/peers/index.json: каждый наблюдатель, его способ, источники,
расписание и последний сверенный день. Каждый день — отдельная папка `/datasets/peers/<наблюдатель>/<ГГГГ-ММ-ДД>/`,
`latest/` ведёт на последнюю. `/datasets/xcheck-crawlcheck/` — адрес, которым пользовались до появления списка, —
ведёт туда же.

## Как добавить наблюдателя

Наблюдателю, который публикует дайджесты наборов инструментов MTL/1 (см. ниже), нужна одна запись в списке, больше
ничего:

```json
{
  "slug": "example",
  "name": "Example Observer",
  "contact": "ops@example.org",
  "method": "digest",
  "window_hours": 24,
  "sources": [{"name": "list", "url": "https://example.org/histor-list.jsonl"}]
}
```

Источник — любой файл, который наблюдатель публикует по https, по строке на каждое чтение сервера: `name` (имя в
реестре), `endpoint`, `digest` (SRI или hex) и `read_at` (RFC 3339), в JSON, JSON Lines или CSV. Лента изменений
CrawlCheck читается в том виде, в каком опубликована. Строка с `digest`, равным null, и полем `outcome` значит, что
наблюдатель не смог прочитать этот сервер. `histor-peers.timer` каждый день запускает все записи (`deploy/peers_check.sh`, `histor/peers.py`); подробнее в [operations.ru.md](operations.ru.md). Наблюдатель с журналом изменений по полям в формате ScraperWatch добавляется со способом `field-diff` и параметрами, как в записи ScraperWatch в `deploy/peers.json`.

## Способ: дайджесты наборов инструментов

Это дайджест набора инструментов MTL/1 ([labels.ru.md](labels.ru.md)). Для каждого инструмента: `name`,
`description` (`""`, если нет), `inputSchema` (`{}`, если нет) и `outputSchema`, только если сервер прислал объект;
инструменты отсортированы по имени в кодовых единицах UTF-16; канонический JSON по RFC 8785; SHA-256 в виде строки
SRI. В спецификации lockfile у CrawlCheck он называется `jcs_v1.tools_sha256` (https://crawlcheck.io/spec/mcp-lockfile).
Проверено 7 ноября 2026 года: оба тестовых вектора CrawlCheck, шесть наборов из записей HISTOR, посчитанные сервисом
CrawlCheck, и собственный сервер CrawlCheck дают у обеих сторон одинаковые дайджесты.

`annotations`, `title` и `icons` в этот дайджест не входят; оба сервиса хранят их под вторым дайджестом — дополнений.
С вечера 7 ноября 2026 года CrawlCheck строит свой `extras_sha256` так же, как HISTOR строит дайджест дополнений (не
по RFC 8785), поэтому совпадают и они: для crawlcheck.io/mcp оба равны `sha256-G44DGgW7…`. Ежедневный запуск
сравнивает только дайджест набора инструментов: в источниках дайджеста дополнений нет.

Каждая опубликованная наблюдателем строка сравнивается с историей HISTOR для этого сервера (`/api/v1/servers/<id>`):

| Вердикт | Что значит |
|---|---|
| `agree` | дайджест HISTOR на момент чужого чтения тот же (между двумя чтениями HISTOR годится любое из них) |
| `agree_nearby` | у HISTOR в тот момент был другой дайджест, но этот HISTOR видел в пределах окна: сервер сменился между чтениями |
| `disagree` | у HISTOR есть дайджесты в пределах окна, и этого среди них нет |
| `histor_no_digest` | у HISTOR нет дайджеста для сервера в пределах окна (не читал или список, который MTL/1 не может посчитать) |
| `not_listed` | HISTOR не знает такого имени и адреса |
| `theirs_no_digest` | другой наблюдатель не смог прочитать список (`digest` равен null, причина в `outcome`) |
| `bad_row` | поле отсутствует или не читается |

Окно, по умолчанию 24 часа, нужно потому, что некоторые серверы меняют список при каждом чтении: 7 ноября четыре из
семи проверенных серверов получали новый дайджест примерно каждые 30 минут. Два наблюдателя тогда совпадают только
«рядом».

Для CrawlCheck запуск читает два источника: его публичную ленту изменений (https://crawlcheck.io/api/v1/mcp/changes,
последние 500 событий, примерно два с половиной дня, поэтому запуск ежедневный) и его еженедельный общий список из
30 серверов, который перечитывается каждый понедельник до 11:30 UTC (https://crawlcheck.io/data/xcheck/histor/latest.jsonl,
датированные выпуски с подписанным заявлением рядом). В папке за день для каждого источника лежат файл в том виде, в
каком его прочитали (`<источник>.input.*`), сравнение (`<источник>.report.json`, `<источник>.report.md`) и
`SHA256SUMS`.

Сверку можно запустить самому, с Python 3.11 или новее и без установки чего-либо:

```bash
python3 scripts/xcheck_digests.py https://crawlcheck.io/data/xcheck/histor/latest.jsonl --out report.json --md report.md
```

Код выхода 0 — ни одного `disagree`, 1 — хотя бы одно, 2 — вход не прочитан.

Первые результаты, 7 ноября 2026 года: первый выпуск общего списка (sha256 `9271b8ac…`) — 30 серверов, 30 `agree`;
лента изменений — 16 строк с дайджестом, 15 `agree`, 1 `histor_no_digest`, 0 `disagree`.

## Способ: изменения по полям

ScraperWatch публикует ежедневный журнал изменений инструментов на постоянной панели удалённых серверов — в виде
JSON-путей со старыми и новыми значениями. Каждый день HISTOR сверяет последний день этого журнала в обе стороны: каждое изменение из их журнала — с записями HISTOR путь за путём, и каждое изменение HISTOR на их панели,
которого нет в их журнале, — с объяснением причины (`histor/peer_xcheck.py`, [operations.ru.md](operations.ru.md)).
Эта сверка читает базу HISTOR, поэтому идёт в своём контейнере с настройками базы. Её параметры (адреса журнала и
панели, агент для robots.txt, время и первый прогон) записаны в её записи в списке. До 7 ноября 2026 года она шла раз
в неделю, после выгрузки датасета.
