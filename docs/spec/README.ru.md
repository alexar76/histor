# Спецификация формата лога прозрачности HISTOR (`histor-tlog/2`) — краткое содержание

> Нормативный текст — только английский: [transparency-log.md](transparency-log.md). Это изложение не нормативно. Другие языки: [English](transparency-log.md) · [Español](README.es.md) · [Français](README.fr.md) · [中文](README.zh.md).

Что фиксирует спецификация:

- **Лист** дерева — один label: W3C Verifiable Credential профиля MTL/1, подписанный ключом лога (`did:key`, Ed25519, cryptosuite `eddsa-jcs-2022`). Вход листа — канонические байты RFC 8785 документа *как он отдаётся*, вместе с proof. `leaf_hash = SHA-256(0x00 ‖ JCS(label))`.
- **Дерево** — RFC 9162 (Certificate Transparency v2): `node_hash = SHA-256(0x01 ‖ left ‖ right)`, доказательства включения и согласованности без изменений.
- **Подписанная голова** (`histor.sth/v1`): `log`, `treeSize`, `rootHash`, `timestamp`; подпись Ed25519 над каноническими байтами всех членов, кроме `signature`, причём `type` внутри подписанных байт — подделать одним документом другой нельзя. Одна голова на размер дерева, навсегда.
- **Правило проверки**: `type` сверяется первым; ключ — только закреплённый (pinned) ключ лога; подписи с ключами и точками малого порядка отвергаются до проверки уравнения (строгое правило Ed25519).
- **Ответ `/check`** (`histor.check/v1`) — подписанное утверждение, что лог держит такой вердикт для такого набора инструментов; это повод проверить, а не доказательство.
- **Чего нет**: подписей издателей (сторона издателя — декларация наборов в реестре или в файле на своём домене), доказательств времени и полноты.
- **`histor-tlog/2` (30.10.2026):** та же голова отдаётся как **checkpoint C2SP** (`GET /checkpoint`: origin, размер, корень в base64, подпись лога по c2sp.org/signed-note, затем строки косигнатур свидетелей по c2sp.org/tlog-cosignature), а сам экземпляр — **свидетель** по c2sp.org/tlog-witness для логов из `HISTOR_WITNESS_LOGS` (`POST /witness/v1/add-checkpoint`, отдельный ключ `witness.key`). Дерево, листы и доказательства не меняются. Векторы проверены эталонными Go-библиотеками (`golang.org/x/mod/sumdb/note`, `github.com/transparency-dev/formats/note`).
- **Векторы** `test-vectors/vectors.json` нормативны: 8 листов, корни для размеров 1–8, все доказательства включения и согласованности, две подписанные головы тестовым ключом, три отрицательных случая. Тест `tests/test_spec_vectors.py` держит код в согласии с файлом.
